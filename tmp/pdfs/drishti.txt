DRISHTI THE PROPOSAL 04
WHAT WE BUILD
An intelligence layer over publicdata.
Drishti should connect meaning, identity, computation and
provenance - then make that layer explorable through
natural language, maps and analytical views.
Discover Connect Analyze Explain Trace
01 / DISCOVER
Find the right evidence
Semantic search across datasets, metadata, publishers,
geography, time and domain.
02 / CONNECT
Resolve shared entities
Canonical districts, states, schemes, organizations,
indicators and temporal concepts.
03 / ANALYZE
Run deterministic computation
SQL, Python, statistics and graph traversal - not
arithmetic hallucinated by an LLM.
04 / EXPLAIN
Translate analysis to insight
Clear findings, context, caveats, alternative explanations
and confidence signals.
05 / TRACE
Show how it was derived
Claim -> analysis -> observation -> transformation ->
authoritative source.
06 / EXTEND
Add domains without rebuilding
A stable semantic layer turns new indicators into
mappings, not bespoke applications.

DRISHTI TRUST MODEL 08
Every claim should carry its derivation.Drishti's credibility should come from a machine-readable evidence chain. The user should be able to move from narrative insight back to
the exact source records and versions used.
Claim -> Analysis run -> Query / code ->
Normalized observations -> Transformations -> Source resources ->
Publisher Version + checksum Retrieval timestamp
FACTS
Directly computed or read from evidence.
ANALYSIS
Statistics, comparisons and relationships produced by explicit methods.
HYPOTHESES
Possible explanations, clearly labeled and never presented as causal fact.

===== PAGE 11 =====

PROJECT
DRISHTI SUCCESS + GUARDRAILS 11
SUCCESS MEANS RELIABILITY
What v0.1 must prove
1 Integration: at least 10 heterogeneous resources mapped into one semantic model.
2 Identity: canonical district/state resolution across the pilot set.
3 Reproducibility: reference questions return the same numerical result against the same data version.
4 Provenance: every displayed number can be traced to source evidence.
5 AI discipline: the LLM cannot introduce unsupported numerical claims.
6 Extensibility: a compatible new indicator requires mapping and validation, not a rebuild.
EXPLICIT NON-GOALS
What Drishti is not
Not a portal replacement
data.gov.in remains a source and public access
layer.
Not a dashboard factory
Charts are outputs, not the core system.
Not a CSV chatbot
Reliable joins come before conversational polish.
Not surveillance
No individual citizen profiling as a product
objective.
Not causal by default
Correlation is labeled as correlation.
Not a Palantir clone
The focus is a narrow India public-data
intelligence layer.
Scope discipline protects trust and speed. Project Drishti / Proposal v0.1

Original Drishti layout, influenced by a monochromeenterprise aesthetic
The proposal intentionally uses a restrained black / off-white palette, thin grid lines, oversized
sans-serif typography, rounded information panels and diagram-led storytelling. This visual
language is inspired by the general design character of Palantir's public website and investor
materials, but uses original graphics, layouts and the Project Drishti identity.
